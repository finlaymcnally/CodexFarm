# Oracle Recovery Notes (2026-02-28)

This is a practical incident record for the Oracle/browser auth failures we hit on 2026-02-28, with the exact fixes that worked.

Use this file when the issue comes back.

## Scope

- Repo: `~/projects/shared/CodexFarm`
- Goal: reliable Oracle browser runs with file uploads
- Fast loop model: `gpt-5-instant` (resolves to `gpt-5.2-instant`)

## Primary Working Fixes

1. Keep Oracle state in a stable home/profile path.
2. If WSL Linux Chromium window is not visible, use Windows PowerShell fallback.
3. Force browser uploads (`--browser-attachments always --browser-bundle-files`) when testing file attach behavior.
4. Use absolute UNC file paths from Windows (`\\wsl$\...`) instead of relative `docs/...`.

## Postmortem Update (2026-02-28)

Root cause of repeated "opened ChatGPT but not logged in" loops in WSL was profile-path drift:

- Some commands were using `/tmp/oracle-home-mcnal/browser-profile`.
- Local wrappers were using `~/.local/share/oracle/browser-profile`.
- Logging into one path does not authenticate the other path.

Canonical profile for this repo is now:

- `ORACLE_HOME_DIR=<repo>/var/oracle`
- `ORACLE_BROWSER_PROFILE_DIR=$ORACLE_HOME_DIR/browser-profile`
- `var/` is git-ignored, so this state is local only and not tracked.

Permanent local wrapper updates applied on 2026-02-28:

- `/home/mcnal/.local/bin/oracle-browser-headless` now launches Chromium via `/home/mcnal/.local/bin/chromium-nosandbox-xvfb`.
- This runs Oracle automation off-screen (no desktop focus/mouse hijack).
- Wrapper default set to `ORACLE_BROWSER_STRICT_ATTACHMENT_ACK=0` to reduce false "attachment not acknowledged" failures.
- Wrapper supports `ORACLE_BROWSER_MANUAL_LOGIN=0` override, but default remains manual-login mode in this environment.
- `./oracle/cleanup-stale.sh` is available to clear stale Oracle/Chromium processes and lock files before reruns.
- `./oracle/seed-profile-from-global.sh` can seed repo-local profile from `~/.local/share/oracle/browser-profile`.

## Windows PowerShell Fallback (Verified Working)

Use this when Linux Chromium does not appear even though the process starts.

### 1) Open dedicated profile and sign in manually

```powershell
$profile = Join-Path $env:TEMP 'oracle-home-mcnal\browser-profile'
New-Item -ItemType Directory -Force -Path $profile | Out-Null
$chrome = Join-Path $env:ProgramFiles 'Google\Chrome\Application\chrome.exe'
if (!(Test-Path $chrome)) { $chrome = Join-Path ${env:ProgramFiles(x86)} 'Google\Chrome\Application\chrome.exe' }
Start-Process -FilePath $chrome -ArgumentList @("--user-data-dir=$profile","https://chatgpt.com/")
```

Important:
- This is expected to be a separate Chrome profile (not your normal one).
- Complete login fully.
- Close that dedicated window before Oracle automation starts.

### 2) Clean stale profile lock/devtools files

```powershell
Remove-Item -Force -ErrorAction SilentlyContinue (Join-Path $profile 'SingletonLock'), (Join-Path $profile 'SingletonSocket'), (Join-Path $profile 'SingletonCookie'), (Join-Path $profile 'DevToolsActivePort')
```

### 3) Set env + absolute file paths

```powershell
$file_ai = "\\wsl$\Ubuntu\home\mcnal\projects\shared\CodexFarm\docs\AI_Context.md"
$file_summary = "\\wsl$\Ubuntu\home\mcnal\projects\shared\CodexFarm\docs\2026-02-28_10.36.12_CodexFarm-docs-summary.md"
$env:ORACLE_HOME_DIR = Join-Path $env:TEMP 'oracle-home-mcnal'
$env:ORACLE_BROWSER_PROFILE_DIR = Join-Path $env:ORACLE_HOME_DIR 'browser-profile'
Set-Location '\\wsl$\Ubuntu\home\mcnal\projects\shared\CodexFarm'
```

### 4) Upload smoke (forced attachments)

```powershell
npx -y @steipete/oracle --engine browser --browser-manual-login --browser-input-timeout 300s --browser-timeout 60m --browser-attachments always --browser-bundle-files --model gpt-5-instant --slug win-oracle-upload-file --force --verbose --prompt "Reply with exactly OK." --file "$file_ai"
```

Expected success signals:
- `Uploading attachment: ...attachments-bundle.txt`
- `All attachments uploaded`
- `Verified attachments present on sent user message`
- summary contains `files=1`

### 5) Real run (forced attachments)


## Known Pitfalls

- The warning `CMD.EXE ... UNC paths are not supported` is expected on these runs.
- Relative `--file docs/...` fails in this mode. Use absolute UNC file paths.
- `about:blank` may appear as a control tab; harmless unless run errors.
- If Oracle reports reattach/ECONNREFUSED with manual-login, close the dedicated profile window and retry with lock cleanup.

## Minimal “Back to Green” Checklist

2. Close dedicated profile window.
3. Run upload smoke with forced attachments and absolute UNC file path.
4. Confirm `files=1`.
5. Run real prompt with both files and confirm `files=2`.
