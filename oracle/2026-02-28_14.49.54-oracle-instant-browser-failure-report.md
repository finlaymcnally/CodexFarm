## Possible causes
1. Wrapper behavior mismatch:
   - The "headless" wrapper hard-enables manual login, which needs an interactive ChatGPT sign-in path.
2. Profile/auth mismatch or stale/invalid session:
   - Cookie DB can contain session-token rows while browser automation still cannot establish a valid ChatGPT session.
3. No interactive login completion path in this agent context:
   - The run waits for manual sign-in but the agent cannot complete an interactive login flow.

## Suggested fixes to try
1. Allow non-manual mode in wrapper for automated contexts:
   - Add an opt-out env/flag so `--browser-manual-login` is not always forced.
2. Improve preflight session validation:
   - Validate active ChatGPT session via browser check (not only cookie DB row presence).
3. Fail faster with actionable message:
   - Detect manual-login wait state early and surface explicit remediation (exact login command/profile path).
4. Add automated smoke assertion:
   - `gpt-5-instant` smoke should hard-fail if no first-token/response within expected latency budget.
