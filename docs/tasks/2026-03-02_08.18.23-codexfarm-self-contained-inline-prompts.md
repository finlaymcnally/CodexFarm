# Make CodexFarm Prompts Self-Contained With Inline Input Text

This ExecPlan is a living document. The sections `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` must be kept up to date as work proceeds.

`docs/PLANS.md` is checked into this repository and this document must be maintained in accordance with `docs/PLANS.md`.

## Purpose / Big Picture

User goal (verbatim intent): CodexFarm agents should receive 100% of required input in the prompt so they only think and output; no searching, no file lookup, no “read JSON from path” dependency.

After this change, recipe pipelines will render prompts that include the full input JSON payload text directly in the prompt body. The observable success signal is prompt logs that show payload text blocks and no instruction to read from a filesystem path.

## Surprises & Discoveries

- Observation: CodexFarm has no general template engine; placeholder support is explicit code in `render_prompt_template(...)`.
  Evidence: implementation now directly replaces `{{INPUT_PATH}}` and `{{INPUT_TEXT}}` in sequence.

- Observation: shipped recipe prompts in this repo were previously path-driven and now use `{{INPUT_TEXT}}` with inline payload sections.
  Evidence: `prompts/recipe_schemaorg_normalize_v1.txt`, `prompts/recipe_schemaorg_to_proprietary_v1.txt`, and `prompts/recipeimport_benchmark_line_label_v1.txt`.

- Observation: prompt token compatibility can stay deterministic in runtime while mode enforcement happens in pack lint.
  Evidence: `render_prompt_template(...)` now replaces both placeholders directly, and `pack_lint.py` checks `prompt_input_mode` against required token and reports `pipeline.prompt_missing_required_token` for mismatches.

## Decision Log

- Decision: implement inline placeholder support in CodexFarm first, then migrate recipeimport templates.
  Rationale: recipeimport alone cannot solve this because CodexFarm currently cannot inject input file contents into template text.
  Date/Author: 2026-03-02 / Codex

- Decision: preserve backward compatibility with existing `{{INPUT_PATH}}` templates.
  Rationale: avoids breaking existing packs and allows incremental migration.
  Date/Author: 2026-03-02 / Codex

- Decision: enforce required prompt token in lint for both modes (`path` requires `{{INPUT_PATH}}`; `inline` requires `{{INPUT_TEXT}}`).
  Rationale: keeps template-mode contract explicit at preflight time and prevents silent runtime prompts missing required input reference.
  Date/Author: 2026-03-02 / Codex

## Context and Orientation

There are two repositories involved:

1. CodexFarm runtime repo at `/home/mcnal/projects/shared/CodexFarm`.
2. recipeimport pack repo at `/home/mcnal/projects/recipeimport`.

CodexFarm is the execution engine that renders prompt templates and launches model calls. recipeimport supplies pipeline JSON definitions, prompt templates, and output schemas. Because prompt text is rendered inside CodexFarm, inline payload support must exist there before recipeimport templates can embed full input JSON.

“Inline payload prompt” means the full input file contents are present directly in the prompt text under a dedicated section. The model should not need to access disk or read by path.

## Plan of Work

Milestone 1 (CodexFarm rendering support): Update `src/codex_farm/pipeline_spec.py` so `render_prompt_template(...)` also replaces `{{INPUT_TEXT}}` with full input file contents (`utf-8`). Milestone 2 (CodexFarm contract + lint + tests): Add an optional pipeline config field such as `prompt_input_mode` with values `path` or `inline` (default `path`). In inline mode, pack lint should fail if prompt template omits `{{INPUT_TEXT}}`. Add/adjust tests in `tests/test_pipeline_spec.py`, `tests/test_pack_lint.py`, and worker-facing tests to prove inline rendering works and path mode remains stable.
