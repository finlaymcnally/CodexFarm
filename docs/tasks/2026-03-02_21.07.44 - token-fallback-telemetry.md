# Problem
Recent `one` jobs executed via fake/no-event Codex produced blank `tokens_*` fields, so recent-job summaries could not report token usage.

# Acceptance Criteria
- `run_codex_exec` writes numeric `tokens_input`, `tokens_cached_input`, `tokens_output`, and `tokens_total` even when no usage event is emitted.
- Fallback provenance is explicit in `usage_json`.
- Existing usage-event behavior remains unchanged when real usage is present.
- Tests cover the fallback path.

# Verification Steps
- `.venv/bin/pytest tests/test_codex_exec.py -q`

# Evidence
- Added fallback-estimate path in `src/codex_farm/codex_exec.py`.
- Added regression test: `test_run_codex_exec_estimates_tokens_when_usage_events_missing`.

# Constraints / Decisions
- Use lightweight `chars_div_4` estimation to avoid adding tokenizer dependencies.
- Keep fallback scoped to rows with completely missing usage fields.

# Rollback Plan
- Revert this commit to restore prior behavior (blank tokens when no usage events exist).
