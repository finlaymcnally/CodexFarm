# Truthful Trace Classification

This ExecPlan is a living document. The sections `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` must be kept up to date as work proceeds.

This document follows `docs/PLANS.md` and must be maintained in accordance with that file.

## Purpose / Big Picture

After this change, CodexFarm trace artifacts and telemetry will stop reporting fake reasoning or action events derived from normal model output text. A user inspecting `.trace.json` or `codex_exec_activity.csv` will either see real explicit trace events that Codex emitted, or a truthful zero when no machine-readable trace was captured.

## Surprises & Discoveries

- Observation: The installed local CLI (`codex-cli 0.114.0`) exposes `--json` on `codex exec` but does not advertise a separate reasoning-trace export flag.
  Evidence: `codex exec --help` in this workspace lists `--json`, `--output-last-message`, and progress flags only.
- Observation: Current trace classification bug affects both reasoning and action counts because recursive payload matching also treats ordinary words like `decision` as action evidence.
  Evidence: `docs/reports/2026-03-14_17.45.16-codexfarm-no-heuristic-reasoning-report.md`.

## Decision Log

- Decision: Scope this patch to removing heuristic payload inference and preserving only explicit top-level `event.type` plus nested `item.type` classification.
  Rationale: That fixes the correctness bug immediately without inventing an upstream reasoning surface we have not actually captured.
  Date/Author: 2026-03-14 / Codex

## Outcomes & Retrospective

Completed the correctness fix. CodexFarm now records action/reasoning trace counts only when Codex emitted an explicit matching `event.type` or wrapped `item.type`, so final `agent_message` payload text can no longer fabricate reasoning or action evidence. The focused `tests/test_codex_exec.py` suite passed after the change.

## Context and Orientation

`src/codex_farm/codex_exec.py` is the only place where Codex JSONL stdout is parsed into events and then persisted into `.trace.json` plus `codex_exec_activity.csv`. The helper `_event_matches_trace_hints(...)` currently checks explicit type hints first, but then falls back to recursive substring scanning over the entire event payload. That fallback is what turns final `agent_message` text into fake reasoning/action trace evidence.

`tests/test_codex_exec.py` already covers positive cases for explicit trace events. This patch adds the missing negative case: the final output payload may contain words like `reasoning_tags`, `analysis`, or `decision`, but those are ordinary model output fields and must not be persisted as trace events.

## Plan of Work

Edit `src/codex_farm/codex_exec.py` so trace classification only inspects the actual event type surfaces that Codex labels: the top-level event `type` and, for wrapped `item.completed` events, the nested `item.type`. Remove the recursive payload-key and payload-value hint scan entirely.

Add a regression test in `tests/test_codex_exec.py` that persists a trace artifact from an `item.completed` `agent_message` whose text contains both reasoning and action hint words. Assert that the trace artifact and returned telemetry counts both stay at zero.

Update the small contract docs that currently describe value-recursive matching as intentional. The updated docs should state that nested wrapper events are still supported, but only through explicit `item.type`, not through payload text heuristics.

No external interface names change. The behavioral contract changes for these persisted fields:

These fields must now represent explicit captured trace events only.
