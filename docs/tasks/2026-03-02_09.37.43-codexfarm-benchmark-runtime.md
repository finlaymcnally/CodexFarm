## Surprises & Discoveries

- Observation: CodexFarm currently uses a flat module layout under `src/codex_farm/` rather than nested per-feature subpackages.
  Evidence: Files such as `/home/mcnal/projects/shared/CodexFarm/src/codex_farm/pipeline_spec.py`, `worker.py`, and `codex_exec.py` are top-level siblings.

- Observation: Existing tests already include recipeimport-specific contracts.
  Evidence: `/home/mcnal/projects/shared/CodexFarm/tests/test_recipeimport_schemas.py` exists and is a natural anchor for benchmark-contract additions.

- Observation: Benchmark parsing must happen before task finalization, but artifact file writes are safest after owner-checked promotion.
  Evidence: Parsing pre-promotion allows terminal `benchmark_contract_error` outcomes; writing pre-promotion can leak stale-owner artifacts if lease ownership changes.

- Observation: Warning-only artifact write failures make benchmark runs look successful while losing diagnostics.
  Evidence: Post-promotion warning path allowed `done` tasks even when benchmark manifests were not emitted.
- Observation: Validation ordering matters in benchmark mode: `validate_json_file_against_schema(...)` must run after line-label calibration, not before, because calibration can clamp or normalize fields (e.g., confidence) that may otherwise fail strict schema validation.
- Observation: Keeping canonicalized predictions only in sidecar artifacts makes the primary task output ambiguous for benchmark consumers.
  Evidence: Prior flow promoted raw staged output and wrote calibrated payload only to `predictions.calibrated.json`.
- Observation: Computing alignment coverage from calibrated/aligned rows hides model omission behavior because missing rows are filled before metrics are written.
  Evidence: `fill_missing_prediction` guarantees one calibrated row per canonical line, making post-fill coverage trivially `1.0`.

## Decision Log

- Decision: Keep new benchmark functionality in dedicated `recipeimport_benchmark_*` modules under `src/codex_farm/`.
  Rationale: This matches current flat-module conventions while keeping benchmark-specific logic isolated from generic pipeline execution.
  Date/Author: 2026-03-02 / Codex

- Decision: Keep extraction mode behavior backward-compatible and expose benchmark mode as an explicit runtime option.
  Rationale: Existing callers depend on current extraction contracts; benchmark behavior must be additive.
  Date/Author: 2026-03-02 / Codex

- Decision: Split benchmark work into pre-promotion parse/calibration and post-promotion artifact writes.
  Rationale: This preserves task state correctness (errors can still fail the task) while keeping staged-output ownership protections intact.
  Date/Author: 2026-03-02 / Codex

- Decision: Treat benchmark artifact write failures as execution failures (retry/error), not warnings.
  Rationale: Benchmark mode’s primary value is deterministic diagnostics; silent artifact loss violates the runtime contract.
  Date/Author: 2026-03-02 / Codex

- Decision: Route `--recipeimport-benchmark-mode line_label_v1` to dedicated pipeline `recipeimport.benchmark.line_label.v1` in run-based CLI flows.
  Rationale: Keeps benchmark prompt/schema assets deterministic and avoids accidental non-benchmark pipeline execution under benchmark mode.
  Date/Author: 2026-03-02 / Codex
- Decision: Move benchmark schema validation to the post-calibration path (raw response parse -> calibration -> schema validation -> artifact emission).
  Rationale: This allows deterministic normalization pass to fix recoverable payload issues before hard JSON-contract enforcement, while still failing hard on irreversible invalid structure.
  Date/Author: 2026-03-02 / Codex

- Decision: Keep a lightweight discovery note in `docs/understandings` for complex benchmark ordering investigation, so downstream reviewers can see why contract checks were reordered.
  Rationale: The repo instruction requires complex-flow discoveries to be externalized, and this one affects runtime correctness.
  Date/Author: 2026-03-02 / Codex

- Decision: Promote calibrated canonical benchmark payload as the task output file and treat raw model payload as debug artifact data.
  Rationale: Makes benchmark consumers read one canonical output contract while still preserving raw response evidence for diagnostics.
  Date/Author: 2026-03-02 / Codex
- Decision: Treat benchmark-mode schema validation exceptions as `benchmark_contract_error` and terminalize immediately.
  Rationale: These represent contract mismatches after calibration and are not expected to improve on retry.
  Date/Author: 2026-03-02 / Codex

- Decision: Define `alignment_coverage` using observed raw-model line indices before fill/calibration, while keeping `aligned_lines` as the post-fill count.
  Rationale: Preserves diagnostic signal for model omissions without changing canonical output shape guarantees.
  Date/Author: 2026-03-02 / Codex
