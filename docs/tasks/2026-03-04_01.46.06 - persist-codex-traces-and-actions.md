# Problem
CodexFarm currently stores prompt/output telemetry but does not persist full per-call JSON event traces, making it hard to audit whether runs used tools/files during benchmarking.

# Acceptance Criteria
- Every `run_codex_exec` call can write a trace artifact containing parsed JSON events, passthrough lines, and action/reasoning event slices.
- Worker runs persist trace artifacts per task attempt under run output.
- `one` and `heads_up.learn` calls also persist trace artifacts in deterministic local locations.
- Telemetry rows include enough trace metadata to locate artifacts quickly.
- Unit/integration tests cover trace persistence and caller wiring.

# Verification Steps
- `.venv/bin/pytest tests/test_codex_exec.py tests/test_worker.py tests/test_cli_integration_contracts.py tests/test_heads_up_integration.py -q`

# Evidence
- Added trace persistence path in `src/codex_farm/codex_exec.py`.
- Added caller wiring in `src/codex_farm/worker.py`, `src/codex_farm/cli.py`, and `src/codex_farm/heads_up.py`.
- Added regression tests for artifact creation and trace path propagation.
- Verification run passed: `........................................................................ [ 90%]` + `........ [100%]`.

# Constraints / Decisions
- Keep trace writing best-effort so task execution never fails if trace persistence fails.
- Persist full JSON events as received; do not attempt to fabricate hidden reasoning traces that the provider does not emit.

# Rollback Plan
- Revert the trace artifact writes and telemetry columns; existing prompt/output behavior remains intact.
