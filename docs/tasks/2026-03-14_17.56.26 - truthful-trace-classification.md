# Truthful trace classification

Problem statement:
Trace persistence in `src/codex_farm/codex_exec.py` currently infers reasoning and action events from ordinary output payload text. That makes `.trace.json` and `codex_exec_activity.csv` report fake trace activity when Codex only emitted a final `agent_message`.

Acceptance criteria:
- `reasoning_event_count` and `trace_reasoning_count` only increase for explicit Codex reasoning event types or explicit nested `item.type` values.
- Ordinary `item.completed` events with `item.type = "agent_message"` do not count as reasoning or action because their text contains words like `reasoning`, `analysis`, or `decision`.
- Existing explicit-event trace tests remain green and a new regression test covers the false-positive payload case.

Verification steps:
- Run `source .venv/bin/activate && pytest tests/test_codex_exec.py -q` from the repository root.

Evidence:
- The new regression test fails on the baseline because the old helper counts `agent_message` payload text as reasoning/action.
- The same command passes after the change.

Constraints/gotchas + brief decision:
- Keep support for explicit nested `item.completed` trace items such as `{"item":{"type":"reasoning"}}`.
- Do not guess at the missing upstream reasoning surface in this patch; report absence honestly instead.

Rollback / compensation plan:
- Revert the code, tests, and docs in this task together if downstream callers depended on the old misleading counts.
