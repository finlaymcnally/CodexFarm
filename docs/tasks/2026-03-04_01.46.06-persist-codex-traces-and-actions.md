# Persist Codex Trace And Action Artifacts

This ExecPlan is a living document. The sections `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` must be kept up to date as work proceeds.

This document follows `docs/PLANS.md` and must be maintained in accordance with that file.

## Purpose / Big Picture

After this change, every Codex execution call in CodexFarm leaves behind a durable trace artifact containing raw JSON events and a narrowed action/reasoning slice, so benchmark audits can confirm what the model did during execution. You can verify this by running a task and checking a `.codex-farm-traces/` artifact file plus matching telemetry metadata.

## Surprises & Discoveries

- Observation: Existing telemetry already parses all JSON events from stdout but only stores counts/types.
  Evidence: `src/codex_farm/codex_exec.py` currently uses `_parse_jsonl_events` for usage extraction and telemetry counts only.
- Observation: Caller wiring assertions were easiest to keep stable by checking trace path structure rather than task-id joins from `list_tasks_for_run`.
  Evidence: `tests/test_worker.py::test_worker_loop_processes_task_with_mocked_codex` needed path-shape assertions after `list_tasks_for_run` did not expose `task_id`.

## Decision Log

- Decision: Implement trace persistence inside `run_codex_exec` instead of adding separate caller-side subprocess wrappers.
  Rationale: All real execution paths already converge here, so this is the only place that guarantees full coverage.

## Context and Orientation

`src/codex_farm/codex_exec.py` is the subprocess boundary. It currently parses stdout JSON lines into event dictionaries, extracts usage tokens, and appends one telemetry CSV row per call. `src/codex_farm/worker.py` calls this function for normal run tasks. `src/codex_farm/cli.py` calls it for `one`, and `src/codex_farm/heads_up.py` calls it for the post-run distiller invocation (`source=heads_up.learn`).

The change must preserve existing reliability contracts: output acceptance, retries, and telemetry writes are best-effort and should not fail execution when auxiliary persistence fails.

## Plan of Work

Add an optional `trace_output_path` argument to `run_codex_exec` and write a helper that persists a JSON artifact with command metadata, prompt, parsed events, passthrough text lines, and derived slices for likely action and reasoning events. Keep this write best-effort.

Extend telemetry schema with trace metadata fields so each invocation row can be linked to the artifact path and summarize action/reasoning event counts. Update migration compatibility constants accordingly.

In `worker.py`, compute a per-attempt trace path under `<run_output_dir>/.codex-farm-traces/<task_id>/<lease_token>.trace.json` and pass it into `run_codex_exec`. In `cli.py` (`one`), write trace files under `<output_dir>/.codex-farm-traces/` using timestamp + short UUID. In `heads_up.py`, write trace files under `<data_dir>/heads_up/traces/` keyed by run id.
