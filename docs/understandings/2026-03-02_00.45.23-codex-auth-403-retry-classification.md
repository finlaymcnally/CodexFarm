summary: "Codex websocket 403 auth failures were classified as generic retryable runtime errors."
read_when:
  - "When debugging repeated worker retries with no output payload"
  - "When Codex stderr mentions websocket/backend-api auth failures"
---

CodexFarm previously had special classification only for rate-limit (`429`) messages. When `codex exec` failed with websocket auth/session errors (for example `wss://chatgpt.com/backend-api/codex/responses` + `HTTP 403 Forbidden`), worker treated them as generic runtime failures, so tasks retried until `max_attempts`.

Result: runs wasted retries and emitted noisy downstream symptoms (`no last agent message`) even though root cause was missing/invalid local Codex login session.

Fix direction: add shared auth-failure text classification in `codex_exec.py`, then consume it in worker/CLI/doctor so auth failures are explicit and worker marks them terminal immediately (no retry loop).
