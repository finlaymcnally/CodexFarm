# Discovery: Benchmark Hook Points In Worker Loop

The safe place to parse benchmark payloads is after local schema validation but before owner-checked staged-output promotion.

Why:

- Parsing before promotion lets benchmark-contract errors fail the task instead of silently succeeding.
- Writing benchmark files before promotion risks stale-owner artifacts if lease ownership changes.
- Writing benchmark files after promotion keeps canonical output ownership safe and avoids mutating task status after `done`.

Current implementation uses this split:

1. Parse + align + calibrate in-memory from staged output (`prepare_line_label_benchmark_artifacts`).
2. Promote staged output with lease-token ownership check.
3. Write benchmark artifacts (`write_line_label_benchmark_artifacts`) only after successful promotion.

This preserves existing retry/terminal logic and staged-output safety while still giving deterministic benchmark diagnostics.

Follow-up implementation note:

- Benchmark artifact writes are now hard failures (`benchmark_artifact_write_error`) rather than warning-only.
- The worker removes promoted output on artifact-write failure so retries/errors do not leave misleading successful payload files.
