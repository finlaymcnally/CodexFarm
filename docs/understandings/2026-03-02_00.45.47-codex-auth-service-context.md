---
summary: "CodexFarm auth succeeds when the calling process sees the same Codex credential home; service contexts must preserve HOME/CODEX_HOME."
read_when:
  - "When CodexFarm works in your shell but fails with auth/login errors in a service or external caller"
  - "When wiring non-interactive CodexFarm calls from another program"
---

- `codex-farm doctor` verifies both Codex CLI availability and a non-interactive `codex exec` smoke call; auth failures are surfaced with explicit "sign in with ChatGPT" guidance.
- Runtime execution (`run_codex_exec`) relies on inherited process environment for Codex credentials; it does not inject a custom credential path.
- If a service/daemon runs under a different user or `HOME`, set `CODEX_HOME` (or `HOME`) to the account that already completed `codex login`, then re-run `codex-farm doctor`.
