---
summary: "Investigated benchmark runtime schema validation ordering and found calibration must precede schema gate for canonical line-label outputs."
read_when:
  - "When adjusting CodexFarm benchmark runtime contract checks for prediction shape and confidence bounds."
  - "When debugging why valid benchmark outputs were being rejected by schema validation."
---

- In benchmark mode, a strict schema check was originally applied before line-label calibration, which means out-of-range values from model output (for example `confidence > 1`) failed immediately even if they were recoverable through deterministic normalization.
- The run loop was therefore able to emit a `benchmark_contract_error` or similar task failure before calibration and diagnostics had a chance to adjust the payload.
- Correct ordering is now: parse raw benchmark response -> align/surface per-line labels -> apply calibration -> validate calibrated payload against schema -> write artifacts/publish result.
- This preserves deterministic normalization behavior and avoids false negatives in schema enforcement while still preserving strictness for irreversible structural violations.
