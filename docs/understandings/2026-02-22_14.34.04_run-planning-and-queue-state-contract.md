# Discovery

`run create`/`process` share one planning path (`_create_run_for_paths`) that always resolves absolute paths, enumerates sorted file inputs, creates a `runs` row, and then enqueues one `tasks` row per file.

The important hidden contract is that `runs.status` is not authoritative on its own: `db.run_status` re-derives run state from grouped task counts and writes back the inferred value. Any change to task transitions in worker code can change user-visible run status semantics.

A second key seam is `runs.config_json`: planning persists `farm_root` (always) and `workspace_root` (optional), and worker code later prefers those persisted values for `--cd` behavior. This makes run resumes deterministic across invocations.
