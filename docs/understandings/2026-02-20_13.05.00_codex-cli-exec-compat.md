summary: "Codex CLI v0.104.0 exec compatibility quirks that affect codex-farm."
read_when:
  - "When editing codex subprocess command construction or doctor checks"
---

Observed in this environment (`codex-cli 0.104.0`):

- `codex exec --ask-for-approval never ...` fails parsing. Approval must be passed globally: `codex --ask-for-approval never exec ...`.
- Running in a non-git directory fails unless `--skip-git-repo-check` is included.
- `codex exec` can emit an expected `OK` answer but still return non-zero due local warning/telemetry shutdown errors. Doctor treats an exact `OK` line as success to avoid false negatives.
- `--output-schema` currently enforces a strict subset where every key in `properties` must also appear in `required`. Optional fields must be modeled as nullable required fields (for example, `\"type\": [\"string\", \"null\"]`).
- `codex exec` can return non-zero while still writing a valid `--output-last-message` payload; codex-farm now accepts non-zero exits when a non-empty output file is produced and lets local JSON Schema validation decide pass/fail.
