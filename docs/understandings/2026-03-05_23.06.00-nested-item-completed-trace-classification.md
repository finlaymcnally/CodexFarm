---
summary: "Nested `item.completed` Codex events can still carry explicit trace types via `item.type` even when the wrapper event type is generic."
read_when:
  - "When trace artifacts show explicit wrapped reasoning/action events under `item.completed`"
  - "When changing trace classification in `src/codex_farm/codex_exec.py`"
---

Modern `codex exec --json` output can wrap meaningful trace payloads inside `item.completed` envelopes. In the failing shape, the top-level event type is just `item.completed`, while the useful classification signal lives in `event['item']['type']` and the excerpt text lives in `event['item']['text']`.

Practical implication: trace slicing cannot rely only on top-level `event['type']`. It still needs an explicit `item.completed` check for nested `item.type`, because Codex may wrap a real reasoning or action item inside that envelope.

Practical non-goal: do not recursively scan normal payload text for hint words. Ordinary `agent_message` output is content, not trace telemetry.
