---
summary: "Nested `item.completed` Codex events carry reasoning/action hints in values, not just top-level event keys."
read_when:
  - "When trace artifacts show `reasoning_event_count=0` despite raw stdout containing reasoning text"
  - "When changing `_event_matches_trace_hints` or `_persist_trace_artifact` in `src/codex_farm/codex_exec.py`"
---

Modern `codex exec --json` output can wrap meaningful trace payloads inside `item.completed` envelopes. In the failing shape, the top-level event type is just `item.completed`, while the useful classification signal lives in `event['item']['type']` and the excerpt text lives in `event['item']['text']`.

Practical implication: `_event_matches_trace_hints(...)` cannot rely only on top-level `event['type']` or dictionary key names. Trace slicing needs both value-aware recursive hint matching and an explicit `item.completed` check for nested `item.type`, otherwise trace artifacts are written successfully but `reasoning_events` stays empty.
