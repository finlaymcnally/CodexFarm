---
summary: "Trace counts should come only from explicit Codex event types or nested `item.type`, never from payload text."
read_when:
  - "When changing trace classification in `src/codex_farm/codex_exec.py`"
  - "When `.trace.json` shows `agent_message` outputs that mention reasoning terms"
---

Current `codex exec --json` traces in this workspace are trustworthy only at explicit type surfaces: top-level `event.type` and, for wrapped `item.completed` events, nested `item.type`.

Recursive payload scanning is unsafe because normal final `agent_message` JSON often contains words like `reasoning_tags`, `analysis`, or `decision`. Those are output content collisions, not trace telemetry.

Practical rule: keep support for explicit wrapper events such as `{"type":"item.completed","item":{"type":"reasoning"}}`, but treat `item.type="agent_message"` as ordinary output even if its text mentions reasoning or actions.
