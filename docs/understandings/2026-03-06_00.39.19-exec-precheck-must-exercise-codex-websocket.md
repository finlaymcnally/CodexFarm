# Discovery

`codex login status` is not a sufficient readiness signal for CodexFarm execution entrypoints.

In the failing recipeimport/CodexFarm transcript, the local Codex session looked logged in, but the first real non-interactive `codex exec` still failed later with websocket `403 Forbidden` against `backend-api/codex/responses`.

# Practical rule

For `one`, `worker`, `process`, and `go`, the default precheck needs to verify both:

- `codex login status`
- a real non-interactive `codex exec` smoke call

Otherwise callers can still create runs or start workers only to fail immediately on the first websocket-backed execution attempt.
