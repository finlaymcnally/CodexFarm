---
summary: "How queue leasing and process orchestration interact in codex-farm."
read_when:
  - "When modifying worker concurrency, retries, or run completion logic"
---

`process` does not spawn nested CLI subprocess workers in v1.

It starts N threads, each running `worker_loop(..., once=True)`. Each worker repeatedly leases queued/expired tasks from SQLite until none are available, then exits. Leasing uses `BEGIN IMMEDIATE` plus atomic row update (`attempts += 1`, lease metadata) to avoid duplicate claims.

Retry behavior is controlled in the worker: on recoverable failure, tasks are requeued until `attempts >= max_attempts`, then marked `error`. Run status is inferred from task counts in `run_status()`.
