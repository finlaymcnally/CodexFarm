---
summary: "Recipe pipelines currently inherit repo-level coding-agent instructions because Codex is launched with --cd at the farm root."
read_when:
  - "When reasoning traces show coding-oriented startup behavior during non-coding recipe tasks"
  - "When changing codex execution context, workspace isolation, or per-pipeline cd behavior"
---

- Recipe pipelines such as `recipe.schemaorg.normalize.v1` and `recipeimport.benchmark.line_label.v1` currently set `codex_cd_mode` to `asset_root`, so worker execution resolves `--cd` to the farm root rather than an isolated scratch directory.
- `run_codex_exec(...)` in `src/codex_farm/codex_exec.py` always passes that resolved directory to `codex exec`.
- In this repository, the farm root contains `AGENTS.md` with coding-agent startup instructions including `Start: run docs list...`, so spawned Codex sessions can spend reasoning tokens on repo onboarding behavior that is unrelated to recipe extraction.
- The recipe prompts themselves are already inline-only (`prompt_input_mode: "inline"` and `{{INPUT_TEXT}}` rendering), so the model does not need repo access for the extraction task. The leak is environmental, not a missing prompt guardrail.
- Practical implication: the strongest fix is to separate non-coding recipe runs from the repo workspace. A sterile `--cd` directory removes repo-local AGENTS discovery. A separate `CODEX_HOME` is useful defense-in-depth if home-scoped Codex guidance or auth/session state should also be isolated.
