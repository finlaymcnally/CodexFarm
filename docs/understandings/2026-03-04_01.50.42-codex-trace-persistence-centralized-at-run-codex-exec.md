summary: "Codex trace/action persistence should be implemented at run_codex_exec to cover all execution entrypoints."
read_when:
  - "When adding new codex execution observability artifacts"
---

`worker`, `cli.one`, and `heads_up.learn` all call `run_codex_exec(...)`, so trace/action capture is only complete when implemented in `src/codex_farm/codex_exec.py` rather than at caller-specific layers.

Practical implication: callers should only provide deterministic `trace_output_path` values; parsing, slicing, and persistence of event traces should remain centralized in `run_codex_exec` so telemetry and artifacts stay consistent across retry paths.
