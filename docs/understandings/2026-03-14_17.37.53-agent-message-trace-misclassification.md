  - "When `.trace.json` files show inconsistent `reasoning_event_count` across similar runs"
  - "When recipeimport prompt samples show some thinking traces for pass1/pass4 but none for pass2 despite the raw event stream looking the same"
  - "When changing trace classification in `src/codex_farm/codex_exec.py`"
---

In the `2026-03-14_17.21.15` Salt Fat Acid Heat benchmark run consumed by recipeimport:

- All `195` raw `.trace.json` files had the same real Codex event shape:
  - `thread.started`
  - `turn.started`
  - `item.completed` with `item.type = "agent_message"`
  - `turn.completed`
- `0` trace files contained an actual nested `item.type = "reasoning"` event.
- But `29` trace files still recorded `reasoning_event_count > 0`.

Why:

- `src/codex_farm/codex_exec.py::_persist_trace_artifact(...)` classifies reasoning/action events with `_event_matches_trace_hints(...)`.
- For `item.completed`, it only gives special treatment to nested `item.type`, then falls back to recursive substring matching over the whole event payload.
- That means plain final `agent_message` JSON can be mislabeled as reasoning if the output payload happens to contain words like `reasoning_tags` or `deliberately`, and mislabeled as action if it contains words like `decision`.

Observed false-positive examples:

- pass1 chunking outputs were counted as reasoning because the final JSON included `reasoning_tags`.
- one pass4 knowledge output was counted as both reasoning and action because its snippet text contained `deliberat` and `decision`.
- structurally similar pass2/pass4 outputs without those substrings stayed at `reasoning_event_count = 0`.

Conclusion:

- The true upstream state for this run was "no actual reasoning events emitted by codex exec".
- Current CodexFarm trace counts add a second bug on top: incidental payload words make some final outputs look like reasoning traces even though they are only `agent_message` results.
