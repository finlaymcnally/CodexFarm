summary: "Legacy telemetry headers can silently misalign new rows; migration must remap by position for stale-header rows."
read_when:
  - "When codex_exec_activity.csv has mixed row widths or missing tokens_reasoning/reasoning_effort columns"
  - "When modifying codex_exec telemetry CSV write behavior"
---

Observed failure mode:
- Some environments kept an old 34-column header while newer codex-farm versions appended wider rows (up to current schema width).
- `csv.DictReader` then mapped only legacy column names and placed extra values into unnamed overflow fields, hiding `tokens_reasoning` and shifting newer columns.

Migration rule used:
- If row width is greater than header width, treat it as a stale-header row from a newer schema and remap by current positional field order.
- If row width is at most header width, remap by the existing header names (legacy schema).
- Recover `tokens_reasoning` from `usage_json` when available and backfill `tokens_total` from input/output when absent.
