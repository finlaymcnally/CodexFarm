---
summary: "Recipe isolation works only when logical scratch settings are frozen with the run while the resolved CODEX_HOME path stays in run-local config."
read_when:
  - "When changing recipe execution isolation, scoped prechecks, or resumed-run config loading"
---

- `codex_execution_context` and `codex_home_profile` belong in pipeline JSON and frozen run assets because they describe logical behavior that must survive pack edits and worker resumes.
- The resolved absolute `codex_home_path` does not belong in repository assets because it is user-local. `run create`, `process`, and `go` now resolve it once from `--codex-home` or `CODEX_FARM_CODEX_HOME_<PROFILE>` and persist it only in `runs.config_json`.
- Runtime prep needs both pieces together: worker/one/Heads Up use the frozen logical execution context to decide between project and scratch `--cd`, then layer the stored `codex_home_path` into subprocess `env_overrides`.
- Scoped prechecks follow the same split. `one`, `process`, and `go` precheck the resolved home before any work starts; `worker --run-id` opens the run first and prechecks its persisted `codex_home_path`; unscoped `worker` stays generic because there is no single correct home for mixed-run leasing.
