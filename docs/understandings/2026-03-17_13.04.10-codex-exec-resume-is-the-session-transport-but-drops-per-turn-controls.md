# `codex exec resume` Is The Session Transport Seam

- Local `codex exec --help` exposes `resume`, so CodexFarm does not need to drive the interactive TUI to reuse a session.
- Local `codex exec resume --help` still supports `--json` and `--output-last-message`, which keeps it compatible with CodexFarm's existing trace/output capture shape.
- Local `codex exec resume --help` does not expose per-turn `--cd`, `--sandbox`, `--ask-for-approval`, or `--output-schema`.
- Practical implication: session boot must lock session-level execution settings, and CodexFarm must own per-task output extraction plus local schema validation for follow-up turns instead of assuming the CLI will re-apply `--output-schema` each time.
