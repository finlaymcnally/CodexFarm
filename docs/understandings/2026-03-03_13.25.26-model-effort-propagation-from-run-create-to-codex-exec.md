---
summary: "How model and reasoning-effort overrides flow from CLI/run config into worker codex exec calls."
read_when:
  - "When checking whether caller-selected model/effort is actually used at execution time"
---

- `run create`/`process`/`go` resolve `--model` + effort aliases in `src/codex_farm/cli.py`, then freeze resolved values into `run_assets/<run_id>/effective_pipeline.json` via `freeze_run_assets(...)`.
- Worker execution prefers frozen assets (`load_frozen_run_assets(...)`) and uses `frozen_spec.codex_model` + `frozen_spec.codex_reasoning_effort` as `selected_model`/`selected_effort`.
- `worker_loop(...)` passes those into `run_codex_exec(model=..., reasoning_effort=...)`.
- `run_codex_exec(...)` always includes `--model <value>` and, when effort is set, appends `--config model_reasoning_effort="<value>"` to the `codex` command.
