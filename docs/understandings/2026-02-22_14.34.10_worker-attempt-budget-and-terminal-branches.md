---
summary: "Worker attempts are consumed at lease-claim time, which shapes retry and terminal-error behavior."
read_when:
  - "When debugging retry counts, expired leases, or why a task failed before re-execution"
---

`lease_one_task` increments `attempts` when a task is claimed, not when a task finishes.

That means:

- normal retries consume one attempt per worker execution try.
- expired-lease reclaims also consume attempts, even if a previous worker crashed before completion.
- `worker_loop` has an explicit guard `attempts > max_attempts` that marks terminal error before processing, which catches over-budget reclaimed tasks.

Execution-time failures (`codex` timeout/error, schema failures, unexpected exceptions) delete any produced output, then either requeue or mark terminal `error` based on `attempts >= max_attempts`.
