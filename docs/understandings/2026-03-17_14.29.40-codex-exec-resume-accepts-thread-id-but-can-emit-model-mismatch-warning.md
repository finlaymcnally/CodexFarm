# `codex exec resume` accepts `thread_id`, but model control is session-level only

- A live local smoke on 2026-03-17 succeeded with:
  - start: `codex --ask-for-approval never exec ... --json 'Reply with exactly {"ok":1}'`
  - resume: `codex exec resume <thread.started.thread_id> --json 'Reply with exactly {"ok":2}'`
- The resumed turn returned the same `thread_id` and a valid final payload, so CodexFarm can currently use the captured `thread.started.thread_id` as the persisted resume key.
- The resumed call also emitted an `item.completed` error message warning that the session was recorded with `gpt-5.3-codex-spark` but resumed with `gpt-5.4`.
- Practical implication: resumed turns are viable, but CodexFarm cannot truthfully claim per-turn model control for `codex exec resume`; any model on resumed turns is upstream-controlled by the existing session/default environment, not by a resume-time flag.
