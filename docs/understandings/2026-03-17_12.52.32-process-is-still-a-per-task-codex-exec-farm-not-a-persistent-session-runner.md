# Process Is Still A Per-Task Codex Exec Farm

- `process` creates a run, enqueues one task per input file, and fans out ordinary worker loops.
- Each worker lease still ends in one `run_codex_exec(...)` invocation for one task payload.
- Harvested `thread_id` and rollout data are observability only today; they are not used to resume or continue a Codex session across tasks.
- Any external caller that wants true session reuse needs a new execution mode, not just fewer tasks or a different task manifest.
