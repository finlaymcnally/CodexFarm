  - "When deciding whether login/auth checks should run before task enqueue"
---

`codex exec` failures from missing login were previously discovered only inside worker attempts, after run/task rows already existed. For external orchestrators this caused avoidable queue churn and max-attempt burn.

`codex login status` is available as a dedicated CLI command and returns clear logged-in/not-logged-in state quickly, so execution commands can preflight auth before run creation or worker leasing.

Practical contract added: default login precheck for `one`, `worker`, `process`, and `go`, with explicit bypass controls (`--no-login-precheck` or `CODEX_FARM_SKIP_LOGIN_PRECHECK=1`) for controlled environments/tests.
