Key control-flow findings from tracing current implementation:

- `process` is an in-process thread fan-out (`ThreadPoolExecutor`), not nested `codex-farm worker` subprocesses.
- Worker safety comes from SQLite leasing (`BEGIN IMMEDIATE` + atomic status/attempt increment), not from Python thread locks.
- Attempt counting increments at lease time, so retry ceilings are enforced consistently even after crashes/lease expiry.
- `run_codex_exec` accepts non-zero Codex exits when a non-empty output payload file exists; final pass/fail is decided by local schema validation.
- Final run state is inferred from task counts in `run_status()`, then synced back to the `runs` table.
