Findings from local investigation on 2026-03-14 with `codex-cli 0.114.0`:

- Interactive/session-backed Codex traces under `CODEX_HOME/sessions/YYYY/MM/DD/*.jsonl` contain `response_item` records whose payload has `type = "reasoning"`.
- Those reasoning items typically include:
  - `summary`: sometimes a plain-language `summary_text` array matching the visible CLI "thinking" blurbs
  - `encrypted_content`: always present in sampled files; this appears to be the full encrypted reasoning payload
- Session files also contain `event_msg` records with `payload.type = "token_count"` and `reasoning_output_tokens`.

Concrete local evidence:

- Historical session files in `/home/mcnal/.codex-alt/sessions/...` contain many reasoning records like:
  - `{"type":"response_item","payload":{"type":"reasoning","summary":[{"type":"summary_text","text":"**Planning bug investigation**"}],...,"encrypted_content":"..."}}`
- A direct authenticated probe of current non-interactive exec:
  - command: `codex --ask-for-approval never exec --skip-git-repo-check --sandbox read-only --model gpt-5.4 --json --output-last-message ... "Think briefly, then reply with exactly OK."`
  - stdout only emitted:
    - `thread.started`
    - `turn.started`
    - `item.completed` with `item.type = "agent_message"`
    - `turn.completed`
  - no reasoning event appeared on stdout
  - stderr included repeated `failed to record rollout items: failed to queue rollout items: channel closed`
  - no new standalone session JSONL artifact was created for the returned probe thread id

Practical conclusion:

- The upstream reasoning surface does exist, but it is not the public `exec --json` stdout stream on this machine.
- The best candidate surface is the local session/rollout artifact under `CODEX_HOME/sessions/...`, specifically `response_item.payload.summary[*].text` for human-readable reasoning summaries and `response_item.payload.encrypted_content` for the encrypted full reasoning item.
- Current blocker: standalone `codex exec --json` did not reliably leave behind that session artifact during the probe, so CodexFarm cannot depend on harvesting it from every exec call without either:
  - an upstream CLI fix/flag that persists the rollout/session for exec mode, or
  - switching to a different Codex surface that guarantees session capture.
