---
summary: "Prompt token mode is a pack-contract concern in lint/model parsing; runtime rendering can stay deterministic by always supporting both placeholders."
read_when:
  - "When adding new prompt placeholders or validating prompt template contracts"
---

- `PipelineSpecModel` is the single source of truth for pack-level prompt mode (`prompt_input_mode`), so lint should read mode from parsed model instead of re-parsing raw JSON keys.
- Runtime prompt construction stays stable by keeping `render_prompt_template(...)` deterministic and token-based (`{{INPUT_PATH}}`, `{{INPUT_TEXT}}`) without branching on mode.
- The right enforcement seam for mode/token mismatch is `pack_lint.py` (`pipeline.prompt_missing_required_token`), which keeps execution paths simple while still giving preflight failures for bad templates.
