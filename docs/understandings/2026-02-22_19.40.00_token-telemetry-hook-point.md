# token telemetry hook point

Discovery summary:

- All real Codex subprocess calls flow through `src/codex_farm/codex_exec.py::run_codex_exec`.
- `process`, `go`, and `worker` all execute Codex from `worker_loop`, so a per-call logger in `run_codex_exec` covers batch activity automatically.
- `one` is the only non-worker execution path; it also calls `run_codex_exec` directly.
- `codex exec --json` emits JSONL events; token usage is available from `turn.completed.usage` (`input_tokens`, `cached_input_tokens`, `output_tokens`).

Design applied:

- Keep logging centralized inside `run_codex_exec`.
- Pass caller context (`source`, pipeline/run/task/worker/input) from `one` and `worker_loop`.
- Write one CSV row per call (`codex_exec_activity.csv`) so post-run analysis does not require DB joins.
