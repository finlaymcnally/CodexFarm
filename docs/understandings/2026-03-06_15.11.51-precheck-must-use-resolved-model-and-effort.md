---
summary: "Why CLI startup prechecks must use the same resolved model and effort as the real run."
read_when:
  - "When debugging why a caller-selected model seems to be ignored before execution starts"
---

- `one`, `process`, and `go` resolve pipeline defaults plus caller overrides before any real Codex execution.
- The startup smoke check lives outside worker execution, so it must receive that resolved model/effort explicitly; otherwise it can fail on a different model than the one the command would actually run.
- `worker` remains generic at startup because it may lease tasks from multiple runs with different frozen configs.
