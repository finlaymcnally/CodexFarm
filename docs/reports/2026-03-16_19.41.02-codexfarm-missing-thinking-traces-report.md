# Missing Thinking Traces Report

## Problem

A real benchmark run used a thinking-capable Codex model, but all saved recipe/knowledge
CodexFarm `.trace.json` artifacts show `reasoning_event_count: 0`.

The operator expected prompt exports and traces to include visible thinking summaries.

## Affected Run

- Benchmark eval root:
  - `/home/mcnal/projects/recipeimport/data/golden/benchmark-vs-golden/2026-03-16_18.10.25/single-offline-benchmark/saltfatacidheatcutdown/codexfarm`
- Processed run root:
  - `/home/mcnal/projects/recipeimport/data/output/2026-03-16_18.10.25/single-offline-benchmark/saltfatacidheatcutdown/codexfarm/2026-03-16_18.11.25`

## What Was Verified

### 1. This is not a recipeimport prompt-export/parser bug

`recipeimport` prompt export reads the already-saved CodexFarm trace payloads and preserves
their reasoning counts faithfully.

The exported prompt log at:

- `/home/mcnal/projects/recipeimport/data/golden/benchmark-vs-golden/2026-03-16_18.10.25/single-offline-benchmark/saltfatacidheatcutdown/codexfarm/prompts/full_prompt_log.jsonl`

shows the same zero reasoning counts that exist in the underlying `.trace.json` files.

### 2. CodexFarm really did run local `codex exec`

Example live trace:

- `/home/mcnal/projects/recipeimport/data/output/2026-03-16_18.10.25/single-offline-benchmark/saltfatacidheatcutdown/codexfarm/2026-03-16_18.11.25/raw/llm/saltfatacidheatcutdown/recipe_correction/out/.codex-farm-traces/996413125bf94396a38d7968b58eec18/ffb26b602ae9443492218516d05340de.trace.json`

Saved `command` field from that trace:

```text
codex --ask-for-approval never exec --cd /home/mcnal/projects/recipeimport/llm_pipelines --skip-git-repo-check --model gpt-5.3-codex-spark --sandbox read-only --config web_search=disabled --config model_reasoning_effort="low" --output-schema ... --output-last-message ... --json ...
```

So the execution stack for the affected tasks was:

1. `recipeimport`
2. CodexFarm
3. local `codex exec --json`

### 3. The saved stdout/event stream contains no reasoning-summary events

The sampled trace payload contains only these event types:

- `thread.started`
- `turn.started`
- `item.completed`
- `turn.completed`

The same sampled trace has:

- `reasoning_event_count: 0`
- `reasoning_events: []`
- `reasoning_event_types: []`

This means there are no dropped reasoning-summary events inside the saved trace artifact. The
reasoning summaries were absent in the upstream event stream CodexFarm persisted.

### 4. The pattern is run-wide

For this run:

- `175` recipe traces exist
- `56` knowledge traces exist
- total recipe+knowledge `.trace.json` files: `231`

All `231` show zero reasoning events.

Line-role is separate and only wrote prompt/response/parsed files plus telemetry, not `.trace.json`
thinking payloads.

## Important Local Model Clue

Local Codex model metadata at:

- `/home/mcnal/.codex/models_cache.json`

for `gpt-5.3-codex-spark` shows:

- `default_reasoning_level: high`
- `default_reasoning_summary: none`
- `supports_reasoning_summaries: true`

Interpretation:

- the model supports reasoning effort
- but current local Codex CLI behavior does not default to emitting reasoning summaries for this
  model in the observed `exec --json` flow

## Relevant CodexFarm Code Path

CodexFarm persists traces in:

- `/home/mcnal/projects/shared/CodexFarm/src/codex_farm/codex_exec.py`

The key behavior:

- `run_codex_exec(...)` launches local `codex ... exec ... --json`
- `_parse_jsonl_events(...)` only records stdout JSONL events actually emitted by Codex
- `_persist_trace_artifact(...)` classifies reasoning events from those stdout events
- if no reasoning-typed events appear on stdout, the saved `.trace.json` correctly records
  `reasoning_event_count: 0`

So unless CodexFarm adds another supported upstream source, it cannot invent missing thinking
traces.

## Prior Related Upstream Investigation

Relevant CodexFarm docs:

- `/home/mcnal/projects/shared/CodexFarm/docs/understandings/2026-03-14_18.12.00-codex-exec-reasoning-upstream-surface.md`
- `/home/mcnal/projects/shared/CodexFarm/docs/reports/2026-03-14_19.36.46-codex-exec-upstream-reasoning-surface-investigation-report.md`

Prior conclusion on this machine:

- interactive/session-backed Codex artifacts can contain reasoning items with `summary_text`
- current standalone `codex exec --json` often does not expose those reasoning items on stdout
- there was no proven reliable artifact handoff from standalone exec into a CodexFarm-harvestable
  side channel

## Working Conclusion

This issue appears to be upstream of recipeimport prompt export.

Most likely root cause:

- CodexFarm correctly persisted the event stream it received
- local `codex exec --json` for `gpt-5.3-codex-spark` with `model_reasoning_effort="low"`
  did not emit reasoning-summary events for this run

## Suggested Next Steps For CodexFarm Agent

1. Confirm whether newer Codex CLI versions expose a non-interactive reasoning-summary flag or
   config knob for `exec --json`.
2. Check whether CodexFarm should explicitly request reasoning summaries when the resolved model
   supports them instead of relying on model defaults.
3. If stdout cannot provide them, investigate whether current standalone exec reliably writes a
   correlated session/rollout artifact that CodexFarm can harvest after each call.
4. Add a blunt runtime warning when:
   - reasoning effort is enabled, but
   - the selected model/config resolves to `reasoning summaries: none`, or
   - observed trace events contain no reasoning surface after a smoke call.
