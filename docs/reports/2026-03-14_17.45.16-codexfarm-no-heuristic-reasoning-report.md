# CodexFarm no-heuristic reasoning report

## Severity

Current CodexFarm reasoning-trace behavior is worse than doing nothing.

Why:

- it fails to persist the real reasoning data the user expects
- it then fabricates partial-looking reasoning traces by scanning normal output payload text for words like `reasoning`, `analysis`, or `deliberat`

That means the artifact can lie in both directions:

- real reasoning may exist but be missing from the trace artifact
- fake reasoning may be reported when there was no captured reasoning trace at all

`reasoning_event_count` is therefore not trustworthy.

## Exact bad behavior

In `CodexFarm/src/codex_farm/codex_exec.py`:

- `_TRACE_REASONING_TYPE_HINTS = ("reason", "thinking", "analysis", "deliberat")`
- `_TRACE_REASONING_KEY_HINTS = ("reasoning", "thinking", "analysis", "deliberat")`
- `_event_matches_trace_hints(...)` falls back to recursive substring matching over the whole event payload
- `_persist_trace_artifact(...)` uses that result to populate:
  - `reasoning_event_count`
  - `reasoning_event_types`
  - `reasoning_events`
  - telemetry CSV `trace_reasoning_count`

This is not trace capture. It is inference from output content.

## Why this is specifically bad

The final `item.completed` `agent_message` payload is model output, not reasoning telemetry.

Scanning that payload for words such as:

- `reasoning`
- `analysis`
- `deliberate`
- `decision`

creates bogus trace evidence from ordinary task content.

Concrete observed false positives:

- pass1 rows counted as reasoning because the final JSON included `reasoning_tags`
- a pass4 row counted as reasoning because snippet text contained `deliberat`
- a pass4 row also counted as action because the output text contained `decision`

These are not actual reasoning-trace events. They are content collisions.

## Why “doing nothing” would be better

If CodexFarm simply recorded:

- raw captured events
- zero reasoning events captured

that would be honest and operationally useful.

The current behavior is worse because it produces a misleading mixed state that looks partially healthy. That wastes debugging time and can cause downstream systems to believe capture succeeded when it did not.

## Correct contract

CodexFarm should follow this rule:

`reasoning_event_count` must only count real captured reasoning-trace events from a known source.

It must never be inferred from normal output payload text.

Equivalent rule for persistence:

- if real reasoning data was captured: persist it
- if real reasoning data was not captured: say so explicitly
- do not synthesize “reasoning events” from output content

## Recommended fix policy

### Immediate policy change

Remove heuristic reasoning classification from final output payload content.

At minimum:

- do not classify `item.completed` with `item.type = "agent_message"` as reasoning based on substring matches inside `item.text`
- do not classify `agent_message` output as action for the same reason

### Allowed positive cases

Only count reasoning when at least one of these is true:

1. Codex emits a dedicated reasoning event type in the machine-readable stream.
2. Codex exposes reasoning via a separate artifact/log/surface that CodexFarm explicitly captures.
3. A documented upstream contract states that a specific field is a reasoning-trace field.

If none of those is true, `reasoning_event_count` should be `0`.

### Required separate work

Find where the real CLI-visible reasoning data actually lives and capture that source directly.

This is a separate problem from trace misclassification, but both need fixing.

## Evidence from investigated run

Run examined:

- `recipeimport/data/golden/benchmark-vs-golden/2026-03-14_17.21.15/single-offline-benchmark/saltfatacidheatcutdown/codexfarm/`

Findings:

- all `195` trace files had `item.type = "agent_message"`
- `0` trace files had a real nested `item.type = "reasoning"` event
- `29` trace files still reported nonzero reasoning counts

That is direct evidence that current nonzero reasoning counts can be fabricated by heuristic matching.

## Ask to the CodexFarm maintainer

Please treat this as a correctness bug, not a presentation bug.

Requested outcomes:

1. Remove heuristic inference from final output payload text.
2. Make trace fields truthy only when backed by real captured reasoning data.
3. Investigate and wire up the actual Codex reasoning source the CLI is showing, if it is available to automation.
4. If automation cannot access that surface today, persist explicit absence instead of guessing.

## Bottom line

The current system is not merely incomplete. It is actively misleading.

Heuristic guessing from model output content should be removed. Real reasoning capture should either be implemented properly or reported as unavailable.
